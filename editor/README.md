# Profile-Editor

Windows에서 `setup.bat`을 한 번 실행한 뒤 `build.bat`으로 빌드합니다.

- 소스 루트: `cmd/editor`
- 로컬 Go 툴체인, Wails CLI, 모듈 및 빌드 캐시: `runtime` (Git 제외)
- 배포 파일: 저장소 최상위의 `Profile-Editor.exe` (Git 추적 대상)

`build.bat`은 `app/release.json`의 버전을 읽어 `-X main.compiledVersion=<버전>`으로
실행 파일에 기록합니다. 업데이트 후 재실행 시 이 값으로 교체된 실행 파일을
확인합니다. 직접 Wails·Go로 빌드할 때도 같은 값을 지정합니다.

`setup.bat`은 시스템에 Go나 Node.js를 설치하지 않습니다. 공식 Go 배포본을
`runtime`에 내려받고, 같은 위치에 고정 버전 Wails v2 CLI와 의존성을 설치합니다.
프런트엔드는 별도 Node.js 빌드가 필요 없는 정적 파일로 구성됩니다. 프로필 탭에서는
기본 정보와 홈페이지 섹션의 순서·노출 여부를 편집하고, 사람·수상·논문·학술활동·
프로젝트·소프트웨어·게시판 탭에서는 각 JSON 항목을 수정·추가·삭제할 수 있습니다.
내용이 없는 홈페이지 섹션은 자동으로 숨겨지며, 항목을 추가하기 전에는 노출할 수
없습니다. 사람은 직접 순서를 바꿀 수 있고, 수상·논문·게시글은 홈페이지와 같은
기준으로 자동 정렬됩니다.
기본 정보는 **이름 → 약력 → 소속 → 직함 → 위치** 순서이며,
약력은 `intro.short_en`·`intro.short_ko`에 저장합니다.

프로젝트·소프트웨어의 **설명**은 영문·국문 목록을 따로 편집합니다. 각 목록에서
항목을 추가·삭제하고 순서를 바꾸며, 입력한 항목 수와 순서가 각각 `notes_en`,
`notes_kr`에 저장됩니다.

왼쪽 메뉴의 사람 아래에 있는 **주제**에서는 논문과 프로젝트가 공통으로 사용하는
하나의 목록을 편집합니다. 영문·국문 이름, 순서와 색상을 수정하고 주제를
추가·삭제합니다. 사용 건수와 삭제 제한은 논문과 프로젝트를 합쳐 계산합니다. 색상 선택기를 사용하거나
`#RRGGBB` 코드를 입력할 수 있으며, 코드를 비우면 홈페이지 타임라인의 자동 색상을
사용합니다. 사용 중인 주제는 연결된 항목을 다른 주제로 변경한 뒤 삭제할 수 있습니다.
모든 변경은 상단의 모두 저장 버튼을 눌렀을 때 `data/settings.json`에 반영됩니다.
공통 목록은 `topics`, 기타 분류의 이름은 `topic_fallback`에 저장합니다.
이전 형식의 별도 목록은 기존 ID와 연결을 유지하며 합치고, 저장할 때 새 형식으로
기록합니다. 같은 ID의 이름·순서는 기존 프로젝트 목록을 우선하며, 설정된 색상과
추가 메타데이터는 보존합니다. 논문의 `topic`과 프로젝트의 `theme`는 모두 같은
`topics[].id`를 참조합니다.

주제 아래의 **학회**, **저널** 탭에서는 독립 목록을 추가·수정·삭제합니다.
주제의 색상 칸을 누르면 10색씩 묶인 팔레트 8개를 표시합니다. 각 주제에서 어느 팔레트의
색이든 하나씩 고를 수 있으며, 다른 주제의 색은 바뀌지 않습니다. 방향키로 색 사이를 이동하고
Enter로 선택할 수 있습니다. **직접 선택**과 HEX 코드 입력, **자동** 색상도 지원합니다.
저널에서는 이름·출판사·ISSN·URL을, 학회에서는 이름·기간·장소·공식 URL을 관리합니다.
**Proceedings 정보**에는 이름·발행기관·권·호·시리즈명·시리즈 권·발행일·ISSN·등재 구분을
순서대로 표시합니다. 권·호는 한 줄에 입력하며, 권·호·시리즈 권은 선택 입력 문자열인
`proceedings_volume`, `proceedings_issue`, `proceedings_series_volume`으로 저장합니다. 등재 구분은
없음·SCIE·SCOPUS·KCI 중 하나만 선택할 수 있습니다.
저널 이름·학술대회명, 저널 출판사·Proceedings 발행기관, 장소, Proceedings 이름, 시리즈명은
다른 탭과 같은 영문·국문 입력란을 사용하며, 각 속성의 `_en`·`_ko`에 저장합니다.
이름은 두 언어 중 하나를 입력하면 됩니다. 이전 단일 문자열도 불러올 때 보존합니다.
ID는 항목을 추가할 때 목록 안에서 중복되지 않게 자동 생성하며, 목록과 입력 폼에
표시하지 않습니다. 이름을 바꿔도 ID는 유지됩니다. 기존 저널·학술대회의 ID와
논문 연결도 그대로 보존합니다. 날짜·URL·ISSN 형식과 기간 순서를 검증합니다.
행사 시작·종료일은 `YYYY-MM-DD`로, Proceedings 발행일은 `YYYY`, `YYYY-MM`,
`YYYY-MM-DD` 중 확인된 정밀도로 입력합니다. **모두 저장** 시
`settings.json`의 `conferences`, `journals` 배열에 반영하며 **변경 되돌리기**로
초안을 복원합니다. 논문 탭에서는 국제·국내 학술지에 저널 선택란을, 국제·국내
학술대회에 학술대회 선택란을 표시합니다. 선택한 항목의 ID를 `journal_id` 또는
`conference_id`에 저장하며, 선택하지 않아도 됩니다. 유형을 학술지와 학술대회 사이에서
바꾸면 이전 유형의 연결을 해제합니다. 연결된 항목은 논문에서 선택을 해제한 뒤
삭제할 수 있습니다. 모두 저장 시 잘못된 유형과 없는 ID의 참조를 검증합니다.

논문 탭의 **서지 정보**에는 학술지 논문의 권·호·쪽수·논문번호(eLocator)·온라인 게재일·
Issue 발행일을 입력합니다. 학술대회 논문에는 쪽수 입력란을 표시합니다. 모두 선택 입력이며,
`volume`, `issue`, `pages`, `elocator`, `online_date`, `issue_date` 문자열 속성으로 저장합니다.
권·호·쪽수·논문번호에는 숫자와 문자를 사용할 수 있고, 날짜는 `YYYY`, `YYYY-MM`,
`YYYY-MM-DD`를 지원합니다. 학술대회 유형으로 바꾸면 쪽수를 유지하고 학술지 전용
서지 입력값을 해제합니다. 등록 정보와 서지 속성으로 홈페이지·CV·인용 복사·서지 파일의
참고문헌을 자동 구성합니다. 학술지는 Issue 발행일 → 온라인 게재일, 학술대회는
Proceedings 발행일 → 학술대회 종료일 순으로 날짜를 적용합니다. 연·월까지만 확인된
날짜는 그대로 사용합니다. 논문 저장 시 기존 `date`는 파생 캐시로 갱신하며,
표시와 정렬은 캐시 대신 등록 정보에서 직접 계산합니다. 서지 정보 아래에서 적용될 날짜와
참고문헌을 미리 볼 수 있습니다.
기본 정보의 수상 선택은 URL 옆에 표시합니다. 상태가 **심사 중**이면 URL·수상·서지 정보
전체를 흐리게 표시하고 마우스·키보드 조작을 막습니다. 기존 값은 보존하며,
**출판됨** 또는 **게재 예정**으로 바꾸면 다시 편집할 수 있습니다.
학술대회 참고문헌 미리보기는 Proceedings·쪽수와 학술대회명·기간·장소를 두 줄로
나누어 표시합니다. 홈페이지에서는 등재 구분을 논문 유형 옆의 문자 태그로 표시합니다.

CV 구성 아래의 설정 탭에서 색상 테마를 선택합니다. 세이지(기본), 오션,
바이올렛, 로즈, 샌드, 슬레이트(다크), 민트, 틸, 스카이, 인디고, 앰버,
그래파이트(다크) 열두 가지 기본 테마와 사용자 지정 테마 3개를 제공합니다.
선택하면 오른쪽 패널에 배경·글자·테두리·강조·상태 알림에 쓰는 26개 색상 코드를 표시합니다.
기본 테마의 코드는 읽기 전용이며, 사용자 지정 테마에서는 이름과 각 색상을 수정할 수 있습니다.
기본 색상을 고르고 **이 색상에서 시작**을 누르면 이름을 유지한 채 해당 기본 테마로 색상을
초기화합니다. 수정 내용은 에디터에 즉시 미리 적용됩니다.
**모두 저장**을 누르면 선택이 `data/settings.json`의 `color_theme`에 저장되어
홈페이지와 CV를 불러올 때 배경, 텍스트, 카드, 버튼 등에 적용됩니다. 사용자 지정 이름·
기본 테마·수정 색상은 `custom_themes`에 저장합니다.
**변경 되돌리기**는 저장한 선택으로 복원합니다. 기존 설정 파일에 이 필드가
없으면 세이지를 사용합니다. 에디터를 다시 실행할 때도 저장된 테마를 따릅니다.

프로필 탭의 자격 항목과 수상 탭에는 선택 PDF 첨부 영역이 있습니다. Explorer에서
PDF 한 개(최대 20MB)를 드롭하면 파일명을 준비하고, **모두 저장**을 눌렀을 때
`data/document`에 파일을 복사하며 각 항목의 선택 `pdf` 필드에 파일명만 저장합니다.
이미 보관한 PDF의 파일명을 직접 입력할 수도 있습니다. 같은 이름의 파일은 덮어쓰지
않고 새 이름으로 보관합니다. **PDF 연결 제거**는 홈페이지 버튼과 JSON 연결을
제거하며 기존 PDF 파일은 보관합니다. 저장 전 변경 되돌리기는 임시 PDF도 정리합니다.

상단의 정사각형 아이콘은 왼쪽부터 변경 되돌리기, 인용수 갱신(Citation update), 모두 저장,
Git push입니다. 인용수 갱신은 변경 되돌리기와 같은 흰색 버튼입니다.
저장·인용수 갱신·Git push를 누르면 진행 팝업이 표시됩니다. 저장 진행률은 실제 JSON
파일 저장 수와 사진 복사 바이트를 기준으로 하며, 검증·최종 확인 단계도 표시합니다.
저장·Git push 완료 팝업은 자동으로 닫히고 오류는 닫기 버튼 또는 Esc로 닫을 수 있습니다.
인용수 갱신은 저장하지 않은 변경을 먼저 저장한 뒤 Go 코드에서 OpenAlex를 직접 조회합니다.
명령줄 도구 `app/tools/refresh-citations.bat`과 같은 갱신 엔진을 사용하며,
논문별 인용수 변경 내역과 최종 집계가 팝업에 표시되며, 결과는 닫기 버튼 또는 Esc로 닫습니다.
OpenAlex 인용수를 조회해 `exports/publication-citations.json`에 반영하며, 기존 KCI 수치는
보존합니다. 네트워크 연결이 필요하며 별도 실행 환경 설치는 필요하지 않습니다.

Git push는 저장하지 않은 변경을 확인 없이 먼저 저장한 뒤, Go 코드로 내보내기와
사이트 검사를 실행하고 Git에서 무시하지 않는 저장소의 변경 파일 전체를 반영합니다.
마지막 커밋을 `commit --amend --no-edit`로 갱신하므로 기존 커밋명이 유지됩니다.
현재 브랜치의 upstream에 정확한 원격 커밋을 지정한 `--force-with-lease`로 전송하며,
원격에 다른 변경이 있거나 Git 충돌·병합·rebase가 진행 중이면 중단합니다.
Git이 PATH에 있어야 하고, Git 인증 및 원격 쓰기·강제 push 권한이 필요합니다.
압축·전송 구간은 Git이 제공하는 진행률을 표시하고, 인증·서버 응답을 기다리는 동안은
대기 상태를 표시합니다. 전송에 실패해도 저장된 데이터와 로컬 커밋은 유지되며,
원격 커밋이 그대로라면 Git push 아이콘으로 재시도할 수 있습니다.
논문의 저자와 수상 관계는 ID 입력란 대신 사람의 이름·소속과 수상의 날짜·제목·기관을
확인하며 선택합니다.
수동 게재지 입력란과 JSON의 `venue`, `venue_en`, `venue_kr` 속성은 제거했습니다.
국내 논문은 저널·학술대회에 등록한 국문·영문 정보를 선택 언어에 맞게 사용하며,
국제 논문은 영문 참고문헌으로 표시합니다. 편집기 빌드는 공통 참고문헌 모듈을
`app/assets/js/publication-bibliography.js`에서 편집기 assets로 복사합니다.

프로필 탭의 학력 항목에는 선택 GPA 획득점수와 만점 입력란이 있습니다. 두 값은
`gpa.value`, `gpa.max` 숫자로 저장되고, 메인 페이지와 CV의 졸업논문명 아래에
`GPA: 3.0 / 4.0` 형식으로 표시됩니다. 두 입력란을 모두 비우면 `gpa`를 생략합니다.
획득점수는 0 이상 만점 이하, 만점은 0보다 커야 하며, 모두 저장을 눌렀을 때 반영됩니다.

학력의 **학위논문 링크 (선택)** 입력란은 `thesis_url`로 저장합니다. http 또는 https
주소를 입력하면 메인 페이지와 CV의 국문·영문 학위논문명에 밑줄과 링크를 표시합니다.
입력란을 비우거나 속성을 생략하면 논문명만 표시합니다.

프로필 탭의 장학 항목에서는 `amount.value` 숫자와 `amount.currency` ISO 3자리 통화
코드를 수정합니다. 장학에는 자유형 `details`를 사용하지 않습니다. 메인 페이지와 CV는
국문에서 KRW, 영문에서 USD를 목표 통화로 사용하며, 원통화와 다를 때만 표시 시점에
Frankfurter v2 rate endpoint의 환율을 지연 조회해 캐시합니다. 조회 실패 시 원금과
원통화를 표시하고, KRW·USD 금액은 모두 일의 자리에서 반올림한 십 단위로 표시합니다.
영문에서는 실제 환산에 사용한 환율 기준일과 환율을 한 줄로 표시합니다. 메인 페이지는
장학 제목 아래 첫 가로선의 오른쪽 위에, CV는 장학 영역의 오른쪽 아래에 표시하며,
환산이 이루어지지 않은 경우 안내를 숨깁니다.
이 금액·통화 변경도 상단 `저장` 버튼을 누르기 전에는 JSON에 반영되지 않습니다.

학술활동 탭은 편집 서비스, 전문 서비스, 학술대회 서비스, 초청 발표, 리뷰를 각각
구분된 목록으로 관리합니다. 분류 헤더의 `+`로 해당 분류 항목을 추가하고, 항목의
위·아래 버튼으로 같은 분류 안의 순서를 바꿀 수 있습니다. 이 순서는 JSON 배열과
홈페이지 표시 순서에 그대로 반영됩니다. 학술활동 항목에는 관계용 `id`가 없으며,
항목이 없는 분류는 홈페이지에 나타나지 않습니다. 모든 분류가 비어 있으면 학술활동
영역 전체가 자동으로 숨겨집니다. 추가·수정·삭제·순서 변경은 편집기 안의 초안으로
유지되고 상단 `저장` 버튼을 눌렀을 때만 `data/academic_activities.json`에 반영됩니다.
이 파일은 `data/version.json`의 공통 버전을 따르며, `editorial_service`,
`professional_service`, `conference_service`, `invited_talks`, `reviews` 배열을 담습니다. 학술활동을 메인 페이지와
CV 섹션으로 배치하는 `settings.json`의 양쪽 섹션 키는
`academic_activities`입니다. 각 활동의 `visible_in_CV`는 생략하면 `true`로 처리되며,
CV 탭의 compact 분류 목록에서 항목을 눌러 포함 여부를 바꿉니다. CV에 선택된 활동이
없으면 학술활동 CV 섹션은 자동으로 숨겨집니다.

리뷰는 완료일을 기억할 수 있도록 `completed_dates`에 `YYYY-MM-DD` 날짜를 하나씩
저장합니다. 편집기에서는 이 완료일 목록을 추가·수정·삭제하며, 숫자형
`review_count`를 직접 입력하거나 JSON에 저장하지 않습니다. 홈페이지의 리뷰 횟수는
`completed_dates` 배열 길이로 자동 계산됩니다.

소프트웨어의 기술은 홈페이지에서 아이콘을 지원하는 목록에서 선택합니다. JSON에서 직접
추가한 미등록 기술도 삭제하거나 이름을 바꾸지 않으며, 편집기에서는 `아이콘 미지원`으로
구분해 그대로 유지합니다.

CV 탭에서는 CV 섹션의 순서·노출 여부와 각 항목의 포함 여부를 따로 정합니다. 항목의
`visible_in_CV`가 없으면 기본적으로 노출되며, CV 탭에서 항목을 누르면 숨김·노출 상태가
전환됩니다. 이 설정을 포함한 모든 변경은 상단 `저장` 버튼을 눌렀을 때만 함께
반영됩니다.

Explorer에서 드롭한 사진은 OS 임시 폴더에만 보관되다가 저장할 때
`data/media`로 복사됩니다. 저장하지 않은 변경이 있으면 창을 닫기 전에 경고가
표시됩니다. 항목에서 미디어를 제거하거나 항목을 삭제해도 공유 미디어의 데이터
유실을 막기 위해 기존 `data/media` 파일은 자동 삭제하지 않습니다.

프로필·프로젝트·소프트웨어·게시판의 미디어 썸네일을 누르면 원본을 팝업으로
확대해 볼 수 있습니다. Esc 또는 × 버튼으로 닫으면 기존 편집 위치로 돌아옵니다.
저장 전 드롭한 이미지도 볼 수 있으며, 미리보기는 데이터를 저장하거나 변경하지 않습니다.

`data/*.json`은 편집기 내부 데이터의 사본이 아니라 홈페이지와 CV가 직접 읽는
원본입니다. 따라서 편집기를 완전히 닫은 상태에서는 JSON을 직접 수정해도 되며,
다음 실행 때 파일의 최신 내용과 ID를 다시 읽습니다. 사람·수상·소프트웨어·프로젝트
테마·논문 주제 ID를 직접 바꿀 때는 `^[a-z0-9]+(?:-[a-z0-9]+)*$` 형식을 지키고
`author_ids`, `award_id`, `theme`, `topic`의 관련 참조를 모두 함께 변경해야 합니다.
프로젝트, 논문과 학술활동 항목 자체에는 의도적으로 ID가 없습니다.

홈페이지와 CV에는 `data/*.json` 변경이 빌드 없이 반영됩니다. 다만
`exports/`의 내보내기 파일과 데이터 보고서는 파생 결과이므로 해당 결과까지
갱신하려면 `app/tools/build.bat`을 실행해야 합니다.

## 특허

**프로필 → 특허**에서 제목·종류, 출원·공개·등록번호와 날짜,
발명자·출원인, 문헌 링크를 관리합니다. 영문·국문 제목 중 하나 이상과 종류,
번호 하나 이상을 입력합니다. 발명자는 **사람** 목록에서 선택하고 순서를
정합니다. 상태는 등록번호 → 공개번호 → 출원번호 순서로 확인하여 등록·공개·출원으로 표시합니다.
날짜는 선택 입력이고 `YYYY-MM-DD` 형식입니다. `+`, 위·아래 이동, 삭제로 목록을
관리하며 **모두 저장** 시 `data/profile.json`의 `patents`에 반영합니다.

홈페이지 기본 위치는 학술활동과 기술 역량 사이입니다. 데이터가 없어도 구성 목록의
위치를 유지하며 공개 화면에서는 숨깁니다. **CV 구성**에서 특허 섹션과 개별 항목의
포함 여부를 정합니다. 이전 형식의 설정은 특허를 숨긴 섹션으로 추가합니다.
홈페이지와 CV에서는 **국내특허 [출원]**, **국내특허 [등록]**처럼 종류·상태별로
묶고 각 구분 안에서 입력 순서를 유지합니다.

## 버전과 파일 경계

사용자가 관리하는 원본·설정·미디어는 최상위 `data/`, 조회·갱신·내보내기 결과는
최상위 `exports/`에 둡니다. 인용수 기록은 `exports/publication-citations.json`에 저장합니다.
데이터 묶음은 `data/version.json`의 버전 하나를 공유하며, 개인 내용을 편집할 때는
버전을 올리지 않습니다. 과거 파일 형식도 읽을 수 있습니다.

프로그램 릴리스는 `app/release.json`, 변경 이력은 `app/releases/`, 업데이트 경계는
`app/update-policy.json`에서 관리합니다. 버전·이력·경계 검사는
`app/tools/check-release.bat`으로 실행합니다. `--preserve-data` 옵션은 개인 데이터의
형식·버전 검사를 생략하고 프로그램 릴리스와 업데이트 경계를 검사합니다.

**설정 → 업데이트**에서 현재 버전과 원본 버전을 확인합니다. **업데이트 확인**을 누르면
원본의 `app/release.json`과 `app/releases/index.json`을 읽고, 필요한 버전의 노트만
최신순으로 표시합니다. 새 버전이 있으면 **업데이트 실행** 버튼이 활성화됩니다.
원본 저장소는 로컬 `app/release.json`의 `upstream`에 기록합니다.

**업데이트 실행**은 편집 중인 변경을 저장한 뒤 원본의 확인된 버전을 내려받습니다.
저장에 실패하면 실행을 중단하고 편집 내용을 유지합니다. 다운로드는 원본 커밋 하나에
고정하며, 프로그램 파일의 백업·적용 진행 상황을 모달에 표시합니다. 적용 후 편집기가
종료되면 외부 PowerShell 프로세스가 실행 파일을 교체합니다. 다음 실행에서 미완료
작업과 실행 파일의 빌드 버전을 확인하고, 적용·되돌림·실패 결과를 업데이트 카드에 표시합니다.

`data/`의 원본 배열·객체와 미디어, `exports/`, `CNAME`, `.git/`, 개인 작업 설정과
`editor/runtime/`는 보존합니다. 개인 데이터 버전, Git의 수정 상태, 기존 코드 해시의
일치는 실행 전제 조건에서 제외합니다. 교체 전 프로그램과 작업 기록은
`editor/runtime/updates/`에 보관합니다.
