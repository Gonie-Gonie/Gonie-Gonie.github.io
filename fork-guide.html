01

저장소 Fork

Fork로 원본 저장소를 내 계정에 복사합니다. Fork한 저장소는 Public이며, push한 파일은 공개됩니다.

  1. 원본 저장소를 열고, 오른쪽 위의 Fork를 누릅니다.
  2. Owner에 내 계정을 선택하고, Repository name을 your-name.github.io로 바꿉니다.
  3. Copy the main branch only를 체크한 상태로 Create fork를 누릅니다.
your-name.github.io의 your-name은 GitHub 사용자명입니다. 같은 이름의 저장소가 이미 있으면 기존 개인 사이트의 사용 여부를 확인합니다.
02

GitHub Desktop으로 Clone

Clone으로 원격 저장소와 연결된 작업 폴더를 PC에 생성합니다.

  1. 내 계정의 fork에서 초록색 Code → Open with GitHub Desktop을 선택합니다. 브라우저가 앱 실행을 물으면 GitHub Desktop으로 엽니다.
  2. Clone a repository 창에서 저장소 주소가 내 계정인지 확인합니다. Local path는 파일을 보관할 폴더입니다.
  3. Clone을 누릅니다. 용도를 묻는 창이 나타나면 For my own purposes → Continue를 선택합니다.
Fork 용도 선택

제목이 How are you planning to use this fork?인 창에서 For my own purposes를 선택한 뒤 Continue를 누릅니다.

03

Profile-Editor로 편집

  1. Clone한 폴더를 탐색기에서 열고 Profile-Editor.exe를 실행합니다. data 폴더 옆에 있는 파일입니다.
  2. 왼쪽 프로필 탭의 기본 정보에서 이름·약력·소속·직함·위치를 바꿉니다. 영문·국문을 각각 입력하고, 아래의 연락처와 사진도 교체합니다.
  3. 논문, 프로젝트, 소프트웨어 등 다른 탭의 내용도 내 정보로 수정하거나 불필요한 항목을 삭제합니다.
원본의 프로필·논문·경력·연락처·사진·첨부파일을 본인의 내용으로 교체합니다. 사람 탭의 본인 저자 정보도 수정합니다.

항목 추가·삭제·순서 변경

프로필의 경력·학력 등 반복 항목은 +로 추가하고, 위로·아래로·삭제로 관리합니다. 프로젝트·소프트웨어는 목록의 드래그 핸들로 순서를 바꿉니다. 학술활동은 같은 분류 안에서 위·아래로 이동합니다.

프로젝트·소프트웨어의 설명은 언어별로 항목을 추가·삭제하고 순서를 정합니다. 각 언어에 최소 한 항목을 입력하며, 영문 설명은 국문보다 적은 항목으로 요약할 수 있습니다.

특허는 프로필 → 특허에서 추가합니다. 발명자는 사람에서 선택하고, 출원·공개·등록번호에 따라 상태가 자동으로 표시됩니다.

논문·분류 입력 순서

  1. 사람에서 기존 본인 항목의 이름·소속을 수정하고, 새 사람으로 공저자를 등록합니다.
  2. 주제에서 필요한 분류명과 색상을 등록합니다. 이 목록은 논문과 프로젝트에서 함께 사용합니다.
  3. 학회·저널에서 필요한 게재처를 등록합니다. 수상 논문이면 수상에서 수상 정보도 입력합니다.
  4. 논문에서 제목과 유형을 입력하고 저자를 선택합니다. 해당하는 주제·학회 또는 저널·수상을 연결합니다. 저자는 논문에 기재된 순서로 배치하고, 유형에 따라 표시되는 서지 정보를 입력합니다.

참고문헌은 등록한 학회·저널 정보와 논문별 서지 정보로 구성됩니다. 수상에 표시되는 논문 정보도 연결한 논문에서 가져옵니다. 사용 중인 주제를 삭제할 때는 연결된 논문·프로젝트의 주제를 먼저 변경합니다.

홈페이지·CV 표시 항목

CV에서 개별 항목 제외

  1. CV 구성을 열고, 목록에서 경력·학력·논문 등의 섹션 이름 왼쪽 펼침 화살표를 누릅니다.
  2. 제외할 항목 행을 누릅니다. 앞의 체크 표시가 사라지면 CV에서 제외됩니다. 다시 누르면 포함됩니다.
  3. 모두 저장을 누릅니다.

항목 데이터와 홈페이지의 표시 상태는 유지됩니다. CV에 포함한 항목이 모두 해제되면 해당 CV 섹션이 자동으로 숨겨집니다.

CV 섹션 전체 숨김·순서 변경

섹션 행의 노출을 누르면 숨김으로 전환됩니다. ↑·↓ 또는 드래그 핸들로 순서를 바꾸고 모두 저장을 누릅니다.

CV의 논문 선택

논문 섹션을 펼치면 제목, 저자 또는 게재지 검색으로 항목을 찾을 수 있습니다. 전체 선택·전체 해제는 검색 결과에 관계없이 모든 논문의 포함 여부를 바꿉니다.

홈페이지 섹션 구성

프로필 → 페이지 구성에서 노출 섹션과 숨긴 섹션을 관리합니다. 각 행의 노출 / 숨김으로 표시를 전환하고, ↑·↓ 또는 드래그로 순서를 바꿉니다. 내용이 없는 섹션은 자동으로 숨겨집니다. 홈페이지와 CV의 표시 설정은 각각 저장됩니다.

색상 테마

  1. 설정 → 색상 테마를 엽니다.
  2. 테마 카드를 선택합니다. 기본 테마 12개와 사용자 지정 테마 3개가 있으며, 선택한 색상은 편집기에 즉시 적용됩니다.
  3. 모두 저장을 누릅니다. 같은 테마가 홈페이지와 CV에 적용됩니다.

사용자 지정 색상

사용자 지정 1~사용자 지정 3 중 하나를 선택하고 테마 이름을 입력합니다. 시작할 기본 색상을 선택한 뒤 이 색상에서 시작을 누릅니다.

오른쪽의 페이지 배경·본문 글자·강조색 등 색상 코드를 #RRGGBB 형식으로 수정하고 모두 저장을 누릅니다. 기본 테마의 색상 코드는 읽기 전용입니다.

이미지·첨부파일·저장

이미지와 PDF

프로필 사진과 프로젝트·소프트웨어·게시판의 이미지는 파일 탐색기에서 편집기의 이미지 영역 또는 미디어 영역으로 드래그합니다. 모두 저장을 누르면 data/media/에 복사됩니다. 썸네일을 누르면 확대되고, Esc 또는 ×로 닫습니다.

자격 항목과 수상의 PDF 영역에 파일을 드래그하면 저장 시 data/document/에 복사됩니다. PDF 연결 제거는 항목과 파일의 연결을 해제합니다. 항목·미디어를 삭제해도 기존 파일은 폴더에 남으므로, 사용하지 않는 파일은 별도로 삭제합니다.

인용수와 단축키

상단의 인용수 갱신 (Citation update)은 수정 중인 내용을 저장한 뒤 OpenAlex 인용수를 조회해 exports/publication-citations.json에 반영합니다.

설정 → 키보드 단축키에서 저장·인용수 갱신·Push·되돌리기·설정 열기의 키 조합을 변경합니다. 기본값 복원으로 기본 단축키를 복원합니다.

저장 적용
입력·순서 변경·CV 포함 여부·테마 설정은 모두 저장으로 로컬 파일에 반영합니다. 변경 되돌리기는 마지막으로 저장한 상태로 복원합니다. 수정한 내용을 웹에 반영하려면 다음 단계에서 저장 후 Git push를 실행합니다.
04

저장·Push

  1. 편집기 오른쪽 위의 디스켓 아이콘 모두 저장을 누릅니다. 수정한 내용이 내 PC의 파일에 저장됩니다.
  2. 맨 오른쪽 위쪽 화살표 아이콘 저장 후 Git push를 누릅니다. 데이터 검사와 내보내기 파일 갱신 후 내 GitHub 저장소로 전송합니다.
  3. 처음 전송할 때 Git 인증 창이 나타나면 fork를 만든 계정으로 로그인합니다. 작업 진행 표시에서 Git push 완료를 확인합니다.
모두 저장: 로컬 파일 저장
저장 후 Git push: 저장·검증·내보내기 갱신·원격 전송
Git 설치·인증 오류

Git을 찾을 수 없습니다가 표시되면 Git for Windows를 설치하고 편집기를 다시 실행합니다. 설치 화면 Adjusting your PATH environment에서 Git from the command line and also from 3rd-party software를 선택합니다.

Git Credential Manager에서 fork를 만든 GitHub 계정으로 인증합니다. 원격 저장소와 현재 브랜치가 내 fork를 가리키는지 확인합니다.

사용자 이름·이메일 설정 오류라면 Git Bash에서 다음 두 명령을 내 정보로 한 번 실행합니다. 이메일은 GitHub에 등록된 주소 또는 GitHub 이메일 설정에서 확인한 noreply 주소를 사용합니다.

git config --global user.name "My Name" git config --global user.email "MY_GITHUB_EMAIL"

오류 메시지를 확인하고 원인을 해결한 뒤 다시 실행합니다.

Push 반영 범위

Git이 무시하지 않는 저장소의 변경 파일 전체를 반영합니다. 마지막 커밋을 갱신하여 기존 커밋명을 유지하고, 원격 상태를 확인한 뒤 전송합니다.

현재 브랜치의 원격 연결·쓰기 권한과 강제 push 권한이 필요합니다. 원격에 다른 변경이 있으면 GitHub Desktop에서 변경 사항을 확인합니다.

05

GitHub Pages 설정

Push 후 내 fork에서 배포 브랜치를 설정합니다.

  1. 내 GitHub 저장소 상단 Settings → 왼쪽 Pages를 엽니다.
  2. Build and deployment의 Source를 Deploy from a branch로 선택합니다.
  3. Branch에서 main과 /(root)를 고르고 Save를 누릅니다.
  4. 배포가 끝나면 같은 화면의 Visit site로 홈페이지를 엽니다. 첫 배포와 변경 반영에는 최대 10분 정도 걸릴 수 있습니다.

https://your-name.github.io/

CV 주소: https://your-name.github.io/cv.html

06

홈페이지·편집기 업데이트

  1. Profile-Editor.exe를 실행하고 설정 맨 아래의 업데이트에서 업데이트 확인을 누릅니다.
  2. 현재 버전과 원본 버전을 비교하고, 변경 이력에서 버전별 수정 내용을 확인합니다. 새 버전이 있으면 업데이트 실행이 활성화됩니다.
  3. 업데이트 실행을 누릅니다. 편집 중인 내용은 먼저 저장됩니다. 다운로드와 프로그램 파일 적용이 끝나면 편집기가 종료되고, 실행 파일 교체 후 자동으로 다시 열립니다.
  4. 다시 열린 편집기의 설정 → 업데이트에서 현재 버전과 적용 결과를 확인합니다. 상단의 저장 후 Git push를 눌러 Git push 완료를 확인하고, Pages 배포 후 홈페이지를 새로고침합니다.
프로필·논문·사진 등 data/의 개인 데이터와 exports/의 파일은 유지됩니다. 직접 수정한 프로그램 파일도 원본 파일로 교체되며, 이전 파일은 editor/runtime/updates/에 백업됩니다.
업데이트 중단·실패

입력 오류나 저장 오류가 표시되면 내용을 수정해 저장하고 다시 실행합니다. 편집기가 자동으로 다시 열리지 않으면 작업 폴더의 Profile-Editor.exe를 실행합니다. 실행 시 미완료 작업을 검사하고, 실행 파일 교체 또는 이전 프로그램 파일 복원을 시도합니다.

설정 → 업데이트에 표시되는 적용·복구 결과를 확인한 뒤 업데이트 확인을 다시 누릅니다.

콘텐츠 갱신

Profile-Editor에서 수정→모두 저장→저장 후 Git push→배포 후 확인

다른 PC나 GitHub 웹에서 수정한 적이 있다면 작업 전에 GitHub Desktop의 Fetch origin으로 확인하고, Pull origin이 나타나면 받아온 뒤 편집기를 실행합니다.

404 오류

저장소 이름이 정확히 your-name.github.io인지, Pages의 Source가 Deploy from a branch인지, Branch가 main / (root)인지 확인합니다. 저장소의 Actions에서 Pages 배포 작업이 끝났는지 확인하고 배포 후 다시 접속합니다. 기본 브랜치 이름을 바꿨다면 Pages에서도 그 브랜치를 선택해야 합니다.

변경 내용 확인

모두 저장 이후 저장 후 Git push 완료 여부를 확인합니다. GitHub에서 data/profile.json 등의 파일을 열어 변경이 올라왔는지 확인하고, Pages 배포가 끝난 뒤 브라우저를 새로고침합니다.

로컬 미리보기

편집기에서 모두 저장을 누릅니다. editor/setup.bat으로 Go를 준비한 뒤 app/tools/serve.bat을 실행합니다. 브라우저에서 로컬 서버 주소로 접속합니다.
